# ¬¬||🧊|| : Cubical Classics

> From program halts in the tale,
> towards program only *Übermensch* is able to run.

`cubical-classics` is an experimental Agda library for constructive and
classical mathematics in Cubical Agda. It develops ordered algebra, Dedekind
and Cauchy completions, constructive real analysis with explicit precision
data, and an `Oracle`-based classical development. The assumption boundary is
part of the library design: modules under `Constructive` do not use `Oracle`,
while modules under `Classical` may do so explicitly.

## Highlights

### Constructive: no `Oracle`

- Univalence and structure identity principles for ordered commutative rings,
  linearly ordered commutative rings, linearly ordered fields, and
  MacNeille-complete ordered fields.
- Generic two-sided located Dedekind completions, with the rational instance
  exported as constructive Dedekind reals.
- HoTT-style Cauchy reals generated from the rational metric space, with
  ordered arithmetic, an ordered Heyting-field structure, and
  precision-indexed Cauchy completeness.
- Precision-indexed metric spaces, located real data, modulated sequences,
  interval results, approximate extrema and IVT results, and the Banach
  contraction principle.
- Cauchy-real series and power series with explicit tail or majorant data,
  algebraic operations, termwise differentiation, recentering, and elementary
  function instances. In particular, the `atanh` value is analytic throughout
  its domain-evidenced strict subunit interval, and the local `log(1+x)` series
  agrees with the global positive logarithm on every strict subunit ball. The
  global positive logarithm is analytic at every point carrying explicit
  positive bounded-domain evidence.

### Classical namespace and explicit `Oracle`

- Choice implies excluded middle through Cubical's Diaconescu theorem; the
  local `Oracle` record packages excluded middle for instance-driven use.
- The classical Dedekind-cut completion of an Archimedean ordered field is a
  MacNeille-complete ordered field, with its universal property.
- The classical real field is characterized as the MacNeille-complete
  Archimedean ordered field generated by the rationals.
- Closed-interval compactness, Heine–Borel, Bolzano–Weierstrass, Cauchy
  completeness, and the intermediate value theorem.

## Quick Start

The known working toolchain is:

- Agda 2.8.0;
- the Cubical Agda library at commit `9216603`.

The project follows Cubical development rather than its latest tagged release.
Starting from a directory in which you want both repositories, the following
commands pin the tested Cubical revision, register it with Agda, and check the
whole library:

```sh
git clone https://github.com/agda/cubical.git
git -C cubical checkout 9216603

AGDA_APP_DIR=$(agda --print-agda-app-dir)
CUBICAL_LIB=$PWD/cubical/cubical.agda-lib
mkdir -p "$AGDA_APP_DIR"
touch "$AGDA_APP_DIR/libraries"
grep -qxF "$CUBICAL_LIB" "$AGDA_APP_DIR/libraries" ||
  printf '%s\n' "$CUBICAL_LIB" >> "$AGDA_APP_DIR/libraries"

git clone https://github.com/kangxyz/cubical-classics.git
cd cubical-classics
agda --build-library
```

The final command reads [`classics.agda-lib`](classics.agda-lib), which records
the Cubical dependency and the project-wide Agda flags. Older Cubical
checkouts, including `v0.9`, are not expected to work.

To import this library from another Agda project, also register the absolute
path to `classics.agda-lib` in the same `libraries` file and add
`depend: classics-0.1` to that project's `.agda-lib` file.

## Stable Entry Points

Import aggregate modules when one is available; individual proof modules are
not automatically stable interfaces merely because their files are visible.

| Module | Scope |
| --- | --- |
| [`Constructive.Algebra.Order`](Constructive/Algebra/Order.agda) | Constructive MacNeille completeness for posets. |
| [`Constructive.Algebra.OrderedCommRing`](Constructive/Algebra/OrderedCommRing.agda) | Ordered-ring properties, Archimedean structure, morphisms, and univalence. |
| [`Constructive.Algebra.OrderedField`](Constructive/Algebra/OrderedField.agda) | Ordered fields, properties, and morphisms. |
| [`Constructive.Analysis.Completions`](Constructive/Analysis/Completions.agda) | Generic Cauchy and Dedekind completions. |
| [`Constructive.Analysis.Metric`](Constructive/Analysis/Metric.agda) | Precision-indexed metric spaces, maps, Cauchy data, and completion instances. |
| [`Constructive.Analysis.Reals`](Constructive/Analysis/Reals.agda) | Constructive real instances, sequences, locators, intervals, IVT, and series. |
| [`Constructive.Analysis.Reals.Calculus.Derivative`](Constructive/Analysis/Reals/Calculus/Derivative.agda) | The current one-variable derivative interface; there is no common calculus aggregate yet. |
| [`Constructive.Analysis.Reals.PowerSeries`](Constructive/Analysis/Reals/PowerSeries.agda) | Cauchy-real power-series theory and elementary instances. |
| [`Constructive.Analysis.FixedPoint`](Constructive/Analysis/FixedPoint.agda) | Constructive fixed-point interfaces and Banach contraction results. |
| [`Classical.Axioms`](Classical/Axioms.agda) | `Oracle`, choice, excluded middle, and `AC→LEM`. |
| [`Classical.DedekindCut`](Classical/DedekindCut.agda) | Oracle-based Dedekind cuts, algebra, completeness, and universal property. |
| [`Classical.DedekindCompletion`](Classical/DedekindCompletion.agda) | Classical MacNeille completeness of constructive Dedekind completions. |
| [`Classical.Analysis.Real`](Classical/Analysis/Real.agda) | The classical real-number base interface. |

The [architecture guide](docs/ARCHITECTURE.md) records the broader stable-entry
map and explains which entries are aggregates or direct modules. The linked

## Contributing

Read the [development guide](docs/DEVELOPMENT.md) and [style guide](STYLE.md)
before changing proofs or public modules. Keep constructive and classical
assumptions on their documented sides of the boundary, type-check the touched
module and its nearest aggregate when practical, and run the repository's
documented diff checks before reporting completion. Changes to stable entry
points or the public mathematical story should update this README and the
architecture guide in the same change.

The library began as hand-written Agda. AI is now used for some routine work
and tedious proof details; mathematical claims remain subject to type checking
and human review. Advice and contributions are welcome.
